# 经文引用校验器

## 用途

给文档里的经文引用做一次体检：每一处引用的书卷、章、节是否真实存在，紧邻的引文是否与数据库原文一致。发现的问题分两级，ERROR 是硬错（经节不存在、范围颠倒、越界），WARN 是可疑（引文与原文明显不一致，可能是默写错误，也可能只是节选或转述）。

它是纯工具：读文件、查数据库、报结果。不解释经文意思，不产出信仰内容。

## 触发场景

- "帮我核验这份文档里的经文引用"、"查一下这段引用是不是编的"
- 提交前跑一次，作为质量闸门（配合 CI 使用）
- 收到别人写的材料，想先确认引用靠不靠谱
- 不适用：要查经文意思（那是研读工具的事）；要排版或翻译。

## 输入与输出

输入：

- 必需：要扫描的 markdown 文件或目录（递归扫描 `.md`）。
- 可选：指定译本 `--version`（默认 CUVS1919，和合本 1919 简体）。

输出：

- 逐条列出 `ERROR`（文件: 书卷 章:节 + 原因）与 `WARN`（文件: 书卷 章:节 + 相似度 + 提示）
- 汇总行：扫描多少文件、多少处引用、多少错误、多少警告
- 退出码：0 通过；1 存在 ERROR（可直接用于 CI 拦截）

## 工作流程

1. **准备数据库。** 校验所依据的经文一律来自数据库，不由模型凭记忆生成。三种来源任选其一，按顺序查找：环境变量 `CHRIST_SKILLS_DATA` 指向的目录；技能或仓库内的 `data/bibles/`；用户本地 `~/biblemate/data/bibles`。数据库是与 biblemate 兼容的 SQLite，表结构 `Verses(Book INT, Chapter INT, Verse INT, Scripture TEXT)`，Book 为新教正典 1 至 66 的序号。没有数据库时用 `bible-data-builder` 从公有领域源数据构建。
2. **运行校验。**

```bash
python scripts/verse_check.py 文档.md
python scripts/verse_check.py 目录/
python scripts/verse_check.py --version CUVS1919 目录/
```

3. **解读结果。** ERROR 必须修正：经节不存在说明引用写错了（章数或节数越界），范围起止颠倒是笔误。WARN 需人工判断：相似度低于 0.85 时，常见原因是节选、转述、用了别的译本，也可能真是引错；把引文换成数据库原文即可消除。
4. **接入流程（可选）。** 把它放进提交前检查或 CI，凡 ERROR 一律拦截，WARN 由人工确认。

## 支持的引用写法

- 中文全名与规范简称：`约翰福音 3:16`、`约 3:16`、`约一 1:9`
- 英文：`John 3:16`、`1 John 1:9`
- 范围：`约翰福音 3:16-18`、`约翰福音 3:16-4:2`（跨章）
- 半角或全角冒号均可：`3:16` 与 `3：16`
- 单字简称有歧义保护：`保罗在 1:23` 这类写法不会被误判为罗马书引用

## 经文依据

本节不适用。本技能属 neutral 级工具，不作出任何教义主张，因此没有经文依据章节的内容。若使用者在信仰场景中使用本工具，其引用的准确性仍需由使用者本人按其所依据的传统复核。

## 争议标注

不适用。本技能只做数据核验，不评价任何译本优劣、不判断宗派立场、不参与教义争议。不同译本的节号体系存在差异（例如个别节在某些版本中被合并），这是数据事实，本技能照实报告越界，不作裁定。

## 质量校验清单

- [ ] 数据库已就位（能查到书卷与章节）
- [ ] 待扫描文件为 UTF-8 编码的 markdown
- [ ] 全部 ERROR 已修正或已确认是数据缺失导致
- [ ] WARN 已逐条人工判断（区分节选、转述与真误引）
- [ ] 用于 CI 时已确认退出码行为符合预期

## 免责与边界

- 本技能只核验「引用是否真实存在」与「引文是否与所用数据库一致」，不判断引用是否恰当、是否断章取义、解释是否正确。这些仍需人工把关。
- 核验结果受所用译本的节号体系限制：某一节在 A 译本存在、在 B 译本被并入相邻节时，会报告为不存在。换译本复核即可。
- 数据库只收录公有领域文本。若使用者自行加入版权译本数据，请自行确认授权范围，本工具不对其负责。
