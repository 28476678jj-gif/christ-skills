# 搜索与传播关键词包

本文件为运营物料，供仓库公开后的曝光优化使用。先把丑话说在前面：**关键词只能提高"被搜到"的概率，不能保证任何榜单位置**。GitHub Trending 没有购买通道，搜索引擎也不接受"保证排名"，凡声称花钱可上热门榜单的服务都是骗局，请勿采信。真正决定传播的是内容质量、真实用户与持续更新。

定位说明：本库对外不以技术概念为招牌。内容权威是圣经、释经文献与古今牧者著作，工具只是载体。以下关键词据此设计，功能词为主、人群词为辅。`claude-code`、`agent-skills`、`workbuddy` 三个标签保留，因为它们是安装宿主的名称，使用者按宿主找技能，属功能信息而非宣传话术。

## 一、GitHub Topics（仓库转公开后由维护者在仓库页设置，建议 12 至 18 个）

```
bible, bible-study, christian, christianity, chinese, chinese-union-version,
sermon, sermon-preparation, exegesis, theology, verse-check, devotional,
bible-data, public-domain, agent-skills, claude-code, workbuddy
```

选择理由：`bible` 系是 GitHub 上信仰类最大流量词，前六个锁定领域与语言；`sermon`、`exegesis`、`verse-check` 覆盖核心功能；`public-domain`、`bible-data` 吸引找数据的开发者；末三个是宿主生态词，让各技能宿主的用户能找到我们。

## 四、传播节奏建议（配合 SPONSORS.md 的平衡原则）

1. P1 完成、仓库转公开时：公众号发官宣长文（讲清"为什么给工具立规矩"），GitHub 设 Topics，README 首段按第二节布局关键词。
2. 知乎：回答"如何评价机器生成的讲章""有哪些好用的查经工具"类问题，附仓库链接，不灌水。
3. 小红书 / B 站：短视频演示"假经文被工具抓包"的真实过程（用本库 verse_check 录屏），这是最有传播力的 30 秒。
4. 每个技能批次发布都是一个内容选题，保持月更以上的真实提交记录，这比任何关键词都管用。

## 五、禁区

- 不买 Star、不刷 Fork、不用机器人账号造势。GitHub 会清，圈子会看见，信誉一旦折损无可挽回。
- 不在教会场景用"上热门"作为项目价值的表述。对外讲搜索优化，对内只讲被更多人用得上。
